The watchlist API as left by Plan 01 (`backend/app/watchlist/routes.py`):
`GET /api/watchlist` → an array of watchlist entries, unchanged from Phase 1.
`POST /api/watchlist` with body `{ "ticker": "<string>" }` → 200 with ONE watchlist entry for the normalized symbol; every price field is `null` until the feed's next poll. On rejection, 400 with `detail` carrying a `code` of `invalid_ticker`, `duplicate_ticker`, or `watchlist_full`.
`DELETE /api/watchlist/{ticker}` → 200 with `{ "ticker": "<normalized>", "removed": <boolean> }`. Removing an absent ticker is NOT an error: it returns 200 with `removed` false, so a double-click or retry is harmless. A malformed symbol returns 400 with the `invalid_ticker` code.
Server-side validation is `^[A-Z]{1,10}$` on the trimmed, uppercased symbol, and the server-side soft cap is 50 tickers.

**Pure accumulator — `frontend/lib/priceHistory.ts`.**
No framework import and no side effect of any kind lives in this file — it is the testable half of the split, exactly as `lib/connection.ts` is to `lib/usePriceStream.ts`.
- `export interface PricePoint { price: number; timestamp: string }`
- `export const MAX_HISTORY_POINTS = 300;`
- `appendTicks(history: Record<string, PricePoint[]>, prices: Record<string, PriceTick>, maxPoints: number): Record<string, PricePoint[]>` — for every ticker in `prices`, append `{ price, timestamp }` only when the incoming tick's `timestamp` differs from the last stored point's `timestamp` for that ticker. The timestamp, not the price, is the new-tick discriminator: two consecutive ticks at the same price are two real observations and must both be recorded, while the same tick object re-delivered on a re-render must not be double-counted. Trim each array with `.slice(-maxPoints)`. Return a new object; never mutate the argument.
- `pruneToWatchlist(history: Record<string, PricePoint[]>, tickers: readonly string[]): Record<string, PricePoint[]>` — keep only entries whose ticker is in the supplied list. This is the ONLY removal signal available: the backend price cache never drops a ticker, so its last price streams forever. Drive pruning from the watchlist entries the page already holds.

**Hook — `frontend/lib/usePriceHistory.ts`.**
A thin `"use client"` wrapper: `usePriceHistory(prices: Record<string, PriceTick>, tickers: readonly string[]): Record<string, PricePoint[]>`. Hold the map in component state; on a change to `prices` fold it through `appendTicks` with `MAX_HISTORY_POINTS`; on a change to `tickers` fold it through `pruneToWatchlist`. Use the same targeted `react-hooks/set-state-in-effect` disable comment `PriceCell.tsx` already carries, with a one-line reason: the accumulator synchronizes with an external event stream, it is not derived from props alone. Memoize the ticker list at the call site so the prune effect does not fire on every render.

**Validation — `frontend/lib/watchlistForm.ts`.**
Pure, mirroring `lib/trade.ts`.
- `export const MAX_WATCHLIST_TICKER_LENGTH = 10;`
- Exported copy constants matching the UI-SPEC Copywriting Contract verbatim: `INVALID_TICKER_MESSAGE` is "Enter a valid ticker symbol (letters only, up to 10 characters)."; `WATCHLIST_REQUEST_FAILED_MESSAGE` is "Couldn't update your watchlist — try again." - `watchlistErrorMessage(detail: unknown, ticker: string): string` — map the backend `code` values Plan 01 emits to copy: the invalid code to `INVALID_TICKER_MESSAGE`, the duplicate code to `duplicateTickerMessage(ticker)`, and anything unrecognised or malformed to `WATCHLIST_REQUEST_FAILED_MESSAGE` rather than raw JSON. **Sparkline — `frontend/components/Sparkline.tsx`.**
A hand-rolled inline SVG, deliberately not a chart-library instance: ten-plus concurrent library chart instances each registering a resize observer and re-rendering every 500 ms is the per-tick recompute cost STATE.md flagged as T-02-13 to address in this phase. Props `{ points: PricePoint[]; width?: number; height?: number }` defaulting to 96 by 28 per the UI-SPEC. With fewer than two points render an empty `<svg>` of the same fixed dimensions so the row does not reflow when the first tick arrives. Otherwise map each point to an x of `(index / (points.length - 1)) * width` and a y of `height - ((price - min) / (max - min || 1)) * height`, and emit one `<polyline>` with `fill="none"` and `strokeWidth={1.5}`. Stroke is `var(--up)` when the last point is at or above the first and `var(--down)` otherwise — the series trend, per the UI-SPEC Color table. Mark the element `aria-hidden="true"`: the sparkline's autoscaled shape is decoration, and the row's signed percent change beside it remains the authoritative statement of how much the price actually moved.
