# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (initialized Phase 1, `frontend/components.json` exists — no re-init) |
| Preset | style: `base-nova`, base color: `neutral`, CSS variables mode, no prefix |
| Component library | base-ui (`@base-ui/react`) primitives, wrapped by shadcn — corrected from Radix in Phase 1's original note, per Phase 2's UI-SPEC |
| Icon library | lucide-react (`lucide-react` in `package.json`, present since Phase 2 but unused until now) — first exercised this phase: `X` icon (14px) for the watchlist row remove control |
| Font | Inter (`next/font/google`, `--font-sans`), `font-variant-numeric: tabular-nums` (`.numeric` utility) on every price/P&L/numeric cell — unchanged |

**No new shadcn primitives are installed this phase.** All new visual elements continue the hand-built `<div>` convention established in Phase 1-2 (`WatchlistRow`, `PositionRow`, `PriceCell`) rather than reaching for shadcn `table`/`card`/`dialog`:

- **Heatmap** — hand-built nested flexbox `<div>`s (D-02, locked — not a treemap library)
- **Sparkline** — hand-rolled inline `<svg><polyline>` (perf-motivated, see RESEARCH.md Anti-Patterns — avoids 10+ concurrent chart-library `ResizeObserver` instances re-rendering on every ~500ms SSE tick)
- **Main chart / P&L chart** — Recharts `LineChart` + `ResponsiveContainer` (D-01, locked — the one place this phase pulls in a charting library, because Recharts already solves axis scaling/tooltip positioning that would otherwise be hand-rolled badly)
- **Watchlist add form** — existing `input` + `button` shadcn primitives (already installed, no new add)
- **Watchlist remove control** — plain icon `button` (existing shadcn `button`, `variant="ghost"`, `size="icon"`) wrapping the new lucide `X` icon — not a new primitive, a new usage of the existing one
- **Chat placeholder panel** — plain styled `<div>` matching the existing panel convention (`bg-card`, `border-border`, rounded), no shadcn `card` component

**New npm dependency:** `recharts@3.10.1` (`cd frontend && npm install recharts`) — verified React 19-compatible, MIT-licensed, legitimate per RESEARCH.md's Package Legitimacy Audit. No other new packages.

## Layout Grid (new this phase)

UI-02 and UI-04 require the full eight-panel layout (header, watchlist, main chart, heatmap, P&L chart, positions table, trade bar, chat placeholder) to fit a wide desktop screen without excess scrolling, and to remain usable — not hidden, not collapsed — at tablet width (D-04).

**Breakpoint:** Tailwind `lg` (≥1024px) is the desktop/tablet threshold. At `lg` and above, the grid layout below applies. Below `lg` (including tablet-portrait widths down to ~768px), every panel stacks in a single vertical column (D-04) — nothing is hidden, nothing collapses to an icon or overflow menu.

**Desktop grid (`lg:` and up):**

```
┌─────────────────────────── Header (full width) ───────────────────────────┐
├─────────────────────────── Trade bar (full width) ─────────────────────────┤
│  Watchlist (fixed ~320px)  │  Main chart                                    │
│  - add form                │  ┌───────────────────────────────────────┐   │
│  - scrollable row list,    │  │ selected ticker + live price (h-96)   │   │
│    each row: ticker,       │  └───────────────────────────────────────┘   │
│    price, %chg, sparkline, │  ┌──────────────────┬────────────────────┐   │
│    remove control          │  │ Heatmap (h-64)    │ P&L chart (h-64)   │   │
│                             │  └──────────────────┴────────────────────┘   │
│                             │  Positions table                              │
│                             │  Chat placeholder (h-64)                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

- Left column: fixed width `320px`, hosts the Watchlist panel only (add form pinned above the scrollable row list).
- Right column: flexible (`1fr`), stacks Main chart → (Heatmap + P&L chart side by side in a 2-col sub-grid) → Positions table → Chat placeholder.
- Trade bar remains full-width beneath the header, unchanged position from Phase 2.

**Tablet stack (`<lg`):** Header → disclaimer text → Trade bar → Watchlist → Main chart → Heatmap → P&L chart → Positions table → Chat placeholder, each full-width, page scrolls vertically. Watchlist's row list itself does not get an inner scroll container at this width — it flows with the page.

**Chart container heights (component-level, not spacing tokens — declared here to satisfy Recharts' explicit-height requirement, see RESEARCH.md Pitfall 1):**

| Element | Height | Rationale |
|---------|--------|-----------|
| Main chart container | 384px (`h-96`) | Most prominent chart on screen; gets the most vertical room |
| P&L chart container | 256px (`h-64`) | Supporting chart, half the visual weight of the main chart |
| Heatmap container | 256px (`h-64`), with `min-h-64` guard | Matches P&L chart for grid rhythm; `min-h` prevents collapse under flex/grid sizing per Pitfall 1 |
| Chat placeholder panel | 256px (`h-64`) minimum | Matches heatmap/P&L chart sizing so Phase 4 inherits an already-correctly-sized slot (D-03) |
| Sparkline (per watchlist row) | 96px × 28px, fixed | Inline SVG, not a chart-library instance — dimensions are a direct `<svg>` prop, not a spacing token |

All declared heights are multiples of 4px, matching the spacing scale's discipline even though they are fixed component dimensions rather than spacing tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, remove-control icon padding, inline error text gap |
| sm | 8px | Compact row padding, watchlist add-form field gap, heatmap cell internal padding |
| md | 16px | Default cell/element spacing, grid row padding, panel internal padding |

## Typography

Unchanged from Phase 1-2 — same four roles, same two weights. No new size or weight introduced this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 (regular) | 1.5 |
| Body | 14px | 400 (regular) | 1.5 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 24px | 600 (semibold) | 1.2 |

Usage in this phase:
- **Label** — heatmap cell ticker symbol + % P&L (rendered inside each cell when it's large enough to hold text — see UI Considerations "overflow" row); Recharts axis tick labels on both the main chart and P&L chart (`tick={{ fontSize: 12 }}`, matching Label size exactly); watchlist add-form input placeholder text ("Ticker").
- **Body** — watchlist add-form input value text, inline watchlist add/remove error text, chat placeholder body copy.
- **Heading** — new section titles: "Watchlist" (unchanged from Phase 1), "Chart" (main chart panel), "Heatmap", "Portfolio Value" (P&L chart panel), "AI Copilot" (chat placeholder); the selected ticker symbol shown atop the main chart.
- **Display** — the selected ticker's live price shown atop the main chart (reuses `PriceCell`'s existing prominence treatment, same as the watchlist row's price cell).

Only weights 400 and 600 exist. Do not introduce 500 or 700.

## Color

Unchanged 60/30/10 split from Phase 1-2. This phase reuses the existing semantic `--up`/`--down` tokens for the heatmap and P&L chart rather than introducing new color tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0d1117` | Page background, main content area (unchanged) |
| Secondary (30%) | `#161b22` | Panel/card backgrounds — extends to the new Heatmap, Main chart, P&L chart, and Chat placeholder panels; borders `#30363d` (unchanged) |
| Accent (10%) | `#209dd7` (Blue Primary) | Unchanged Phase 1 reservations (header wordmark, watchlist row hover/selected left-border stripe, keyboard-focus ring) **plus one new reservation this phase:** the main chart's selected-ticker line stroke — links the chart visually to the same blue "this is selected" indicator already used on the watchlist row, rather than introducing a third meaning for blue |
| Destructive | `#dc2626` | No true destructive action exists this phase — watchlist ticker removal is instant with no confirmation dialog and is non-destructive to money/positions (only resets that ticker's sparkline history, expected per CONTEXT.md). The shadcn `destructive` button variant stays unused. The remove control itself uses neutral `--muted-foreground` → `--foreground` on hover, deliberately **not** `--down`, to avoid overloading the P&L semantic color as a UI-chrome hover state. |

Accent reserved for: header wordmark text color, watchlist row hover/active left-border stripe, keyboard-focus outline ring, main chart selected-ticker line stroke (new this phase). Not used for heatmap cells, sparklines, or the P&L chart line — those are gain/loss data and use the semantic palette below, not the brand accent.

**Purple Secondary `#753991`** — unchanged from Phase 2 (Buy button fill). No new usage this phase.

**Semantic status palette** (unchanged tokens, reused — not reintroduced, extended to two new consumers this phase):

| State | Value | Usage |
|-------|-------|-------|
| Up | `#16a34a` | Existing: uptick price flash, positions-table positive P&L/%chg. **New this phase:** heatmap cell fill (`bg-up/70`) for profitable positions; sparkline stroke when the accumulated series is trending up; P&L chart line stroke when total portfolio value is at or above the $10,000 starting baseline |
| Down | `#dc2626` | Existing: downtick price flash, positions-table negative P&L/%chg, Sell button outline/text. **New this phase:** heatmap cell fill (`bg-down/70`) for losing positions; sparkline stroke when trending down; P&L chart line stroke when total portfolio value is below the $10,000 starting baseline |

**Accent Yellow `#ecad0a` — explicit resolution for this phase (chat placeholder panel):**

Both Phase 1 and Phase 2's UI-SPECs reserved Accent Yellow for "Phase 4 AI/chat highlight" without ever defining its exact treatment (message bubble color? send-button fill? avatar accent?). This phase introduces the first chat-adjacent UI element — the empty reserved placeholder panel (D-03) — but deliberately does **not** introduce Yellow on it. Locking in a color decision on a panel with no functional chat content yet would risk a mismatched or wasted precedent once Phase 4 actually designs the message bubbles, send button, and loading indicator. The chat placeholder therefore uses the same neutral empty-state treatment as every other empty panel in this app: Secondary `#161b22` background, `#30363d` border, `--muted-foreground` heading/body text — no brand color, no icon accent. **Accent Yellow remains fully unused through Phase 3.** Phase 4's UI-SPEC is the correct place to define its reserved-for list once the chat panel's real content is designed.
