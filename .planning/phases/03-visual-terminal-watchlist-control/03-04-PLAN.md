## Phase Goal

**As a** trader watching a simulated portfolio, **I want to** see my whole portfolio at a glance and curate which tickers the terminal tracks, **so that** the terminal shows me what I care about and how I am doing without reading numbers row by row.

<objective>
Deliver the two "at a glance" visualizations: a treemap where every position is a rectangle sized by its share of the portfolio and coloured by its profit or loss, and a main chart that draws whichever ticker the user clicks in the watchlist.

Purpose: PORT-08, WATCH-05, the heatmap half of TEST-03, and D-01/D-02. The heatmap is the phase's headline visual; the main chart is what turns the watchlist from a list into a selector.
Output: the pure `heatmap` derivation and layout module with its test suite, the `Heatmap` and `HeatmapCell` components, and the `MainChart` component fed by the price history Plan 02 already accumulates.
</objective>

Locked decisions this task implements:
- D-02: the treemap is a hand-built nested flexbox layout, not a treemap library and not the charting library's built-in treemap component. This is a deliberate, recorded choice consistent with Phase 1-2's hand-rolled row and cell components.

**Pure module — `frontend/lib/heatmap.ts`.** No framework import, no side effect, no element measurement.
- `HeatmapItem { ticker: string; value: number; weight: number; pnlPercent: number | null }`
- `HeatmapRow { items: HeatmapItem[]; weight: number }`
- `HEATMAP_LABEL_MIN_WEIGHT = 0.06` — below this share of the portfolio a cell is too small to hold its text legibly, so the component hides the label and keeps the fill. The threshold lives here rather than in the component so it is one named number rather than a magic value in JSX.
- `deriveHeatmapItems(rows: PositionRowData[] | null): HeatmapItem[] | null` — null in, null out, preserving the loading signal the positions table already relies on. Otherwise value each position as `quantity * price`, dropping any position whose price is null (an unpriced position has no honest area). Sum those values; when the sum is zero return an empty array rather than dividing, so no weight is ever NaN or Infinity. Weight is `value / total`, carrying `changePercent` through untouched as `pnlPercent`. Sort descending by weight. Apply no minimum-size floor and no clamping of any kind: a cell's area is the position's real share of the portfolio, and a floor that made a tiny position visible would be a lie about its size.
- `squarify(items: readonly HeatmapItem[], containerAspect?: number): HeatmapRow[]` — the Bruls/Huizing/van Wijk row-building heuristic. Walk the descending-sorted items, accumulating a current row while adding the next item improves (lowers) that row's worst aspect ratio, and closing the row and starting a new one when it does not. Each returned row carries its item list and the sum of its items' weights. Return a new array; never mutate the input. Every input item appears in exactly one row: partition, not sample.

**Cell — `frontend/components/HeatmapCell.tsx`.**
Props `{ ticker: string; weight: number; pnlPercent: number | null; showLabel: boolean }`. The root is a `<div>` whose only inline style is `flexGrow: weight` — the browser's flex engine does the proportional sizing, so this component computes no pixels, reads no bounding rectangle, and registers no resize observer. Fill is `bg-up/70` when `pnlPercent` is at or above zero and `bg-down/70` otherwise, with a thin border in the border token so adjacent cells stay distinguishable, `min-w-0` and `overflow-hidden` so content never forces a cell wider than its share, and 8px internal padding.

When `showLabel` is true the cell renders the ticker at the Label typography role over the signed percent through `formatPercent` with the `numeric` class. That percent is not decoration: it is the non-colour channel that makes profit and loss readable to someone who cannot distinguish red from green, exactly as the direction glyph beside every flashing price cell already does. Give the cell an accessible title combining the ticker, its weight as a percentage of the portfolio, and its signed P&L percent, so the same information survives even when the label is hidden at small sizes. Render text as ordinary JSX children only; introduce no raw-HTML injection prop anywhere.

## Flagged assumptions

Recorded rather than silently decided.

1. **PORT-08 (edge probe returned unclassified/unresolved).** No source artifact states how a position whose ticker has no cached price should appear in the heatmap. Assumption: it is excluded from the treemap entirely and the remaining weights renormalize to 1, because a rectangle can only be honestly sized from a real value, and the positions table already shows that position with an em dash price. It is not drawn at zero width and not given a placeholder area.
2. **WATCH-05 (edge probe returned unclassified/unresolved).** No source artifact states what should happen to the main chart when the currently selected ticker is removed from the watchlist. Assumption: the accumulator prunes that ticker's history, so the chart falls back to its select-a-ticker prompt on the next render; the selection is not silently reassigned to a neighbouring row, because a chart quietly switching to a different security is worse than an empty prompt.
3. **Label legibility threshold.** The UI-SPEC records the label-hiding rule as a backstop with the exact threshold left to in-browser judgment. Assumption: a weight of 0.06 (six percent of the portfolio) as the initial named constant, adjustable at UAT without touching the layout algorithm.
4. **Squarify heuristic fidelity.** RESEARCH.md Assumption A1 notes the row-building heuristic was cross-checked against secondary sources rather than the original paper. Assumption: a subtle deviation would produce less square rectangles but still a correctly weight-proportional partition, which is what PORT-08 requires; the unit tests assert the partition property, not the aspect ratios.
5. **Phase-goal user story.** ROADMAP.md's Phase 3 `**Goal:**` line is not in "As a / I want to / so that" form; the story above restates that line's own words and adds no scope.

| T-03-12 | Denial of service | Client-side price history feeding the main chart on every SSE tick | medium | mitigate | The accumulator caps each ticker at `MAX_HISTORY_POINTS` (300), so the chart's series length is bounded regardless of session duration; the chart itself performs no accumulation and holds no timer. |
