Assemble the final layout. Every panel already exists, is already fed its data, and already handles its own loading, empty, and error states; this task moves them into position and changes no props, no state, no memo, and no fetch handler.

Locked decisions this task implements:
- D-03: the chat panel occupies a reserved slot in the grid rather than being omitted.

**Structure — `frontend/app/page.tsx`.**
Keep the root shell and the header exactly as they are. Inside `<main>`, raise the gap between stacked panels to 32px, matching the UI-SPEC's layout-gap token.

Order inside `<main>`, top to bottom and unchanged between widths: the simulated-data disclaimer paragraph first, then the trade bar full width, then a two-column region.

The disclaimer stays the first element inside `<main>` at both widths, above the trade bar and above every panel that shows a money figure. A layout change that pushed it below the fold or beneath a value panel would leave a persuasive, entirely fabricated portfolio on screen with nothing framing it — the whole reason the sentence exists.

The two-column region is a flex container that is column-direction by default and switches to row-direction at the `lg` breakpoint, with a 32px gap. Its first child is the watchlist wrapper: full width below `lg`, and at `lg` and above a fixed 420px width that does not shrink. Its second child is the flexible column: `flex-1` with a minimum width of zero, holding, in order, the main chart, then a sub-grid that is one column below `lg` and two equal columns at `lg` and above containing the heatmap then the P&L chart, then the positions table, then the chat placeholder.

The minimum-width-zero constraint on the flexible column is load-bearing and not cosmetic: a flex child defaults to a minimum width derived from its content, and a responsive-container chart inside one will push the whole row wider than the viewport and produce horizontal scrolling. Setting it to zero is what lets the charts shrink to their share of the row instead.

Do not set a height on any panel wrapper. Each chart owns its own box height precisely so it cannot resolve to zero; a wrapper height set here would fight that and reintroduce the collapse.

**Left-column width — `frontend/app/page.tsx` and `frontend/components/Watchlist.tsx`.**
The UI-SPEC's desktop diagram calls the watchlist column roughly 320px, but that predates the row gaining a sparkline cell and a remove control. The five-column row template consumes 316px of fixed width before the ticker column gets anything, so a 320px column with 24px padding on each side leaves 272px of content — 44px short before the ticker even renders. Set the column to 420px and reduce the watchlist panel's own padding to 16px, which leaves 388px of content against 316px of fixed columns plus roughly 48px for the ticker: it fits with margin. Reduce the watchlist row's horizontal padding to 8px for the same reason. Change nothing about the sparkline's 96px width, which the UI-SPEC fixes.

**Tablet and below.**
Because the two-column region is column-direction by default, everything below `lg` already stacks in exactly the declared order — header, disclaimer, trade bar, watchlist, main chart, heatmap, P&L chart, positions table, chat placeholder — in one vertically scrolling page. Verify no panel carries a `hidden`, `lg:block`, or truncating class that would remove it below the breakpoint, and that the watchlist's row list has no inner scroll container at this width so it flows with the page. Nothing is added to hide or collapse anything; this is a consequence of the structure, not a separate branch.

**Empty-panel stability.**
Every panel renders its own chrome and heading in all three of its states, so a watchlist with zero tickers, a portfolio with zero positions, and a history with zero snapshots each keep their panel in place at its normal size showing its own empty state. Do not conditionally unmount a panel on empty data anywhere in the page: the grid's column widths and panel order must not shift with the data.
