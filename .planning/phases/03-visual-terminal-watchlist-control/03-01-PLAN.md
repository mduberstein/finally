## Phase Goal

**As a** trader watching a simulated portfolio, **I want to** see my whole portfolio at a glance and curate which tickers the terminal tracks, **so that** the terminal shows me what I care about and how I am doing without reading numbers row by row.

<objective>
Prove the watchlist-curation path end to end on one slice: a ticker typed into the watchlist panel persists to SQLite, is picked up by the already-running `MarketFeed` on its next poll, streams over the existing SSE connection, and grows a sparkline in its own row — and a remove control takes it back out and resets that ticker's history.

Purpose: WATCH-02, WATCH-03, WATCH-04, the frontend half of TEST-03, and D-05. This is the phase's tracer: it is the only slice that crosses every layer Phase 3 touches (a brand-new backend package, a write route, the `watchlist` table, the live feed, a new pure `lib/` module, a new component, and the page). Output: the `backend/app/watchlist/` package owning the whole `/api/watchlist` surface, the pure `priceHistory` accumulator and its hook, the `watchlistForm` validator, a `Sparkline` component, a `WatchlistAddForm`, and per-row remove controls.
</objective>

**Rejection models — `backend/app/watchlist/models.py`.**
Mirror `app/portfolio/models.py` exactly. Base `WatchlistRejected(Exception)` with a `code` class attribute and a `detail() -> dict` returning that code plus the data the UI copy needs. Subclasses: `InvalidTickerError(ticker)` with code `invalid_ticker`; `DuplicateTickerError(ticker)` with code `duplicate_ticker`; `WatchlistFullError(limit)` with code `watchlist_full`. The backend supplies a machine-checkable payload only — the exact sentences live in the frontend.

**Service — `backend/app/watchlist/service.py`.**
Plain functions with no FastAPI dependency, so Phase 4's chat flow can import and call them directly rather than re-implementing validation — the same rule `app/portfolio/service.py` documents for `execute_trade`.
- Module constants: `MAX_WATCHLIST_TICKERS = 50` and a compiled `re` pattern for one-to-ten uppercase letters.
- `normalize_ticker(ticker: str) -> str` — strip then uppercase, then match against the pattern; raise `InvalidTickerError` when it does not match. Uppercasing before validation is what lets a user type lowercase.
- `add_ticker(ticker: str) -> str` — normalize, open `connect()` inside `contextlib.closing`, count existing rows for `DEFAULT_USER_ID` and raise `WatchlistFullError` at the cap, then `INSERT OR ABORT INTO watchlist (id, user_id, ticker, added_at) VALUES (?, ?, ?, ?)` with `uuid.uuid4().hex` and `datetime.now(UTC).isoformat()`. Catch `sqlite3.IntegrityError` and re-raise as `DuplicateTickerError` — the `UNIQUE (user_id, ticker)` constraint is the single source of truth for duplication, so there is no read-then-write race. Commit and return the normalized ticker.
- `remove_ticker(ticker: str) -> bool` — normalize, then `DELETE FROM watchlist WHERE user_id = ? AND ticker = ?`. Return whether any row was affected. A ticker that is not present affects zero rows and is NOT an error: the operation is idempotent by contract, so a double-click or a retry is harmless.
- Every statement binds values through `?` placeholders. No SQL anywhere in this package is assembled by interpolation of any kind — the rule `01-SECURITY.md` locked in and `02-SECURITY.md` re-confirmed.

**Router — `backend/app/watchlist/routes.py`.**
`create_watchlist_router(cache: PriceCache) -> APIRouter`, the same factory shape as `create_portfolio_router`. This module takes ownership of the WHOLE `/api/watchlist` surface: relocate the existing `GET` handler and the `_watchlist_entry` response shaper out of `main.py` and into this file unchanged, so one module owns one resource instead of the read living in the app entrypoint and the writes living elsewhere.
- `WatchlistAddRequest(BaseModel)` with a single `ticker: str` field. No id, no timestamp, no price — the server owns all three.
- `GET /api/watchlist` — unchanged behaviour: `await run_in_threadpool(db.watchlist_tickers)` then one `_watchlist_entry(ticker, cache.get(ticker))` per ticker.
- `POST /api/watchlist` — call `add_ticker` through `run_in_threadpool`, then return `_watchlist_entry(normalized, cache.get(normalized))`. Returning the full entry shape rather than a bare acknowledgement is what lets the page append the new row immediately; a ticker the feed has not polled yet simply has every price field `None`, which the existing `PriceCell` null path already renders as an em dash. That covers the one-poll gap with no special casing.
- `DELETE /api/watchlist/{ticker}` — call `remove_ticker` through `run_in_threadpool` and return `{"ticker": <normalized>, "removed": <bool>}` with status 200 whether or not a row existed.
- Both writes catch `WatchlistRejected` and re-raise as `HTTPException(status_code=400, detail=error.detail())`. Use 400, not 422, for the same reason the trade endpoint does: FastAPI already emits 422 for request-shape failures, and the frontend must be able to tell a malformed body from a refused-but-well-formed symbol.

`backend/app/watchlist/__init__.py` re-exports the three exception classes, the base, `add_ticker`, `remove_ticker`, `normalize_ticker`, and `create_watchlist_router` through `__all__`, matching `app/portfolio/__init__.py`.

**Pure accumulator — `frontend/lib/priceHistory.ts`.**
No framework import and no side effect of any kind lives in this file — it is the testable half of the split, exactly as `lib/connection.ts` is to `lib/usePriceStream.ts`.
- `export interface PricePoint { price: number; timestamp: string }`
- `export const MAX_HISTORY_POINTS = 300;`
- `appendTicks(history: Record<string, PricePoint[]>, prices: Record<string, PriceTick>, maxPoints: number): Record<string, PricePoint[]>` — for every ticker in `prices`, append `{ price, timestamp }` only when the incoming tick's `timestamp` differs from the last stored point's `timestamp` for that ticker. The timestamp, not the price, is the new-tick discriminator: two consecutive ticks at the same price are two real observations and must both be recorded, while the same tick object re-delivered on a re-render must not be double-counted. Trim each array with `.slice(-maxPoints)`. Return a new object; never mutate the argument.
- `pruneToWatchlist(history: Record<string, PricePoint[]>, tickers: readonly string[]): Record<string, PricePoint[]>` — keep only entries whose ticker is in the supplied list. This is the ONLY removal signal available: the backend price cache never drops a ticker, so its last price streams forever and a ticker's disappearance can never be inferred from the prices map. Drive pruning from the watchlist entries the page already holds.

**Hook — `frontend/lib/usePriceHistory.ts`.**
A thin `"use client"` wrapper: `usePriceHistory(prices: Record<string, PriceTick>, tickers: readonly string[]): Record<string, PricePoint[]>`. Hold the map in component state; on a change to `prices` fold it through `appendTicks` with `MAX_HISTORY_POINTS`; on a change to `tickers` fold it through `pruneToWatchlist`. Use the same targeted `react-hooks/set-state-in-effect` disable comment `PriceCell.tsx` already carries, with a one-line reason: the accumulator synchronizes with an external event stream, it is not derived from props alone. Memoize the ticker list at the call site so the prune effect does not fire on every render.

**Validation — `frontend/lib/watchlistForm.ts`.**

**Sparkline — `frontend/components/Sparkline.tsx`.**
