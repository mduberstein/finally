## Phase Goal

**As a** visitor opening FinAlly for the first time, **I want to** see ten default tickers streaming live prices in a dark trading terminal, **so that** I can watch the market move without reloading the page.

<objective>
Turn the working-but-plain tracer page into the dark trading terminal the UI-SPEC specifies, and give the watchlist its real loading and empty states.

Purpose: the terminal aesthetic is a product requirement (UI-01), not polish — a Bloomberg-style data-dense dark surface is what makes this read as a trading workstation. This plan also lands the frontend test runner every later frontend plan verifies against.
Output: the dark theme tokens, a Header/Watchlist/WatchlistRow component structure, and a vitest harness.
</objective>

Create `frontend/components/WatchlistRow.tsx` exporting `WatchlistRow`, taking a ticker symbol and an optional price value plus an optional percent change. The row is focusable and carries a transparent left border that becomes the accent `#209dd7` stripe on hover, on selection, and on keyboard focus, with the accent focus ring on focus-visible. Track the selected row in page state — clicking a row selects it. Loading the selected ticker into a main chart area is Phase 3 scope (WATCH-05) and is not part of this task.

Create `frontend/components/Watchlist.tsx` exporting `Watchlist`, taking the watchlist entries and the live price map. It owns three states:
- Loading — while the initial watchlist fetch has not resolved, render exactly 10 skeleton rows using the shadcn skeleton component, laid out in the same three-column grid as a real row so the layout does not jump when data lands.

Reduce `frontend/app/page.tsx` to composition: fetch the watchlist, call `usePriceStream()`, hold the selected ticker, and render `Header` above `Watchlist`. Keep the visible simulated-data disclosure line from Plan 01 — do not drop it during the refactor. Use a 32px gap between the header and the main content per the UI-SPEC spacing scale.

Phase 1 targets desktop viewports at 1280px and wider. Tablet-width responsive behavior is UI-04, explicit Phase 3 scope, so do not add breakpoint handling here.

## Flagged assumptions

1. **Semantic status variable names.** The UI-SPEC fixes the three status color values but not their token names. Assumption: naming them for their role (up / down / reconnecting) rather than their color, so Plans 03 and 04 read clearly at the call site.
2. **Foreground text colors.** The UI-SPEC fixes backgrounds, borders, and accents but does not name a text color. Assumption: `#e6edf3` primary and `#8b949e` secondary — both clear WCAG AA on `#0d1117` and match the GitHub-dark family the specified backgrounds come from.
3. **Row selection with no destination.** The UI-SPEC reserves the accent for a "hover/selected left-border indicator", but the selected ticker has nowhere to go until the Phase 3 main chart exists. Assumption: track selection in page state and render the stripe now, so the interaction the UI-SPEC describes is real rather than inert.
