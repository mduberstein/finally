# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | base color: `neutral`, style: shadcn CLI default (not overridden) |
| Component library | Radix primitives (via shadcn) |
| Icon library | lucide-react (shadcn default) |
| Font | Inter (via `next/font`), `font-variant-numeric: tabular-nums` on all price/numeric cells |

**Initialization is part of this phase's scaffolding** (Phase 1 is a walking-skeleton phase that builds the whole app for the first time — no `frontend/` directory exists yet). The plan/executor must run, in order:

1. Scaffold the Next.js app at `frontend/` — TypeScript, Tailwind CSS, App Router, static export (`output: 'export'` in `next.config`) — per CLAUDE.md's fixed stack.
2. `npx shadcn@latest init -b neutral -d` inside `frontend/` (non-interactive, base color `neutral`, accepting CLI defaults for everything else). This generates `components.json`, the Tailwind CSS-variable theme tokens, and `globals.css`.
3. Layer the project's dark-terminal background/border/accent values (below) on top of the generated neutral theme by overriding the relevant CSS variables in `globals.css` — do not hand-roll a separate theme system.
4. Set `shadcn_initialized: true` in this file's frontmatter once step 2 completes (executor or next UI-SPEC revision updates it).

Anticipated shadcn components for this phase's scope: `table` (or `card` rows), `badge` (connection status label), `skeleton` (loading placeholder rows). No third-party registries.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, connection dot padding |
| sm | 8px | Compact row padding, badge padding |
| md | 16px | Default cell/element spacing, grid row padding |
| lg | 24px | Section padding (header, watchlist panel) |
| xl | 32px | Layout gaps between header and main content |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (not expected to be used in this phase's simple layout) |

Exceptions: none.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 (regular) | 1.5 |
| Body | 14px | 400 (regular) | 1.5 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 24px | 600 (semibold) | 1.2 |

Usage in this phase:
- **Label** — column headers ("TICKER", "PRICE", "CHG %"), connection status text ("Connected" / "Reconnecting" / "Disconnected"), uppercase with letter-spacing.
- **Body** — % change values, secondary row text.
- **Heading** — section title ("Watchlist"), app wordmark "FinAlly" in the header.
- **Display** — the live price value in each watchlist row (must be the most prominent number on screen; uses `tabular-nums`).

Only two weights exist in this phase: 400 and 600. Do not introduce 500 or 700.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0d1117` | Page background, main content area behind the watchlist grid |
| Secondary (30%) | `#161b22` | Header bar background, watchlist panel/card background; borders `#30363d` (muted gray, never pure black) |
| Accent (10%) | `#209dd7` (Blue Primary) | Header wordmark "FinAlly", watchlist row hover/selected left-border indicator, focus outline ring on any focusable element |
| Destructive | `#dc2626` | Downtick price-flash background tint only; no destructive user actions exist in this phase (watchlist add/remove is Phase 3 scope) |

Accent reserved for: header wordmark text color, watchlist row hover/active left-border accent stripe, keyboard-focus outline ring. Not used for price flashes, not used for the connection dot (those use the separate semantic status palette below).

**Semantic status palette** (distinct from the 60/30/10 brand accent — used for transient state, not brand identity):

| State | Value | Usage |
|-------|-------|-------|
| Price up | `#16a34a` | Uptick flash: brief low-opacity green background tint on the price cell, fading over ~500ms via CSS transition |
| Price down | `#dc2626` | Downtick flash: brief low-opacity red background tint on the price cell, fading over ~500ms via CSS transition |
| Connected | `#16a34a` | Header connection dot — stream healthy |
| Reconnecting | `#eab308` | Header connection dot — stream retrying |
| Disconnected | `#dc2626` | Header connection dot — stream down |

Accent Yellow `#ecad0a` and Purple Secondary `#753991` (both fixed by CLAUDE.md's project-wide palette) are not exercised by any Phase 1 element — Purple is reserved for submit buttons (Phase 2 trade bar), Accent Yellow is reserved for future AI/highlight treatment (Phase 4). Recorded here so later UI-SPECs don't reintroduce them inconsistently.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

> Element classification and applicable-category list were produced by running the compiled
> `ui-consideration-probe.cjs` engine (not hand-picked) on three elements: watchlist grid
> (list-collection), connection status indicator (interactive-control ∪ static-content — the
> heuristic's initial `static-content`-only classification was corrected via the propose-then-confirm
> `elements` override to also raise its `loading`/`error` categories, since MARKET-03's three-state
> dot is exactly a loading/error indicator), and header (nav). 15 applicable considerations resulted.

Applicable state considerations resolved: 13 covered, 2 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | watchlist grid (list-collection) | 🧪 backstop | If the watchlist API/SSE returns zero tickers (not expected given the seeded default of 10 per WATCH-01/INFRA-01), the grid renders the empty-state heading "No tickers being tracked" and body "Your watchlist will populate automatically when the app starts." instead of an empty table |
| loading | watchlist grid (list-collection) | ✅ covered | Before the first SSE snapshot arrives, the watchlist grid renders 10 skeleton placeholder rows (shadcn `skeleton` component) matching the final row layout, replaced by live ticker rows once data arrives |
| error | watchlist grid (list-collection) | ✅ covered | On SSE stream failure, watchlist rows continue displaying their last known price/% change (never cleared or blanked); the header connection dot turning red with label "Disconnected" is the sole error surface — no per-row error state exists |
| populated | watchlist grid (list-collection) | ✅ covered | In the populated state the grid shows exactly 10 rows (AAPL, GOOGL, MSFT, AMZN, TSLA, NVDA, META, JPM, V, NFLX), each displaying ticker, live price, and % change, with brief green/red background flashes on price ticks |
| partial | watchlist grid (list-collection) | 🧪 backstop | A ticker row shows a "—" placeholder in the price and % change cells until that specific ticker's first SSE tick arrives, rather than a blank cell or a misleading zero value |
| overflow | watchlist grid (list-collection) | ✅ covered | Price and % change render in fixed-width `tabular-nums` columns sized for the largest expected value; ticker symbols are ≤5 characters and require no truncation or wrapping in this phase |
| zero-one-many | watchlist grid (list-collection) | ✅ covered | The watchlist always renders exactly 10 rows in Phase 1 (fixed seeded ticker count per WATCH-01); no zero/one/variable-count layout behavior is required until watchlist curation (WATCH-02/03) ships in Phase 3 |
| loading | connection status indicator (interactive-control) | ✅ covered | While the SSE connection is retrying, the header connection dot renders yellow `#eab308` with the text label "Reconnecting" |
| error | connection status indicator (interactive-control) | ✅ covered | When the stream is down, the header connection dot renders red `#dc2626` with the text label "Disconnected", and recovers to green `#16a34a` with label "Connected" automatically once the backend returns, with no user action required |
| overflow | connection status indicator (static-content) | ✅ covered | The connection status label is always one of three fixed short strings ("Connected" / "Reconnecting" / "Disconnected"); no dynamic or user-generated content exists that could overflow the header's connection-status area in Phase 1 |
| long-text | connection status indicator (static-content) | ✅ covered | Same fixed 3-string enum as the overflow consideration above — no long-text handling is required for the connection status label |
| loading | header (nav) | ✅ covered | The header shell (wordmark) has no async loading state of its own; the only dynamic content inside it is the connection status indicator, whose loading state is covered separately above |
| error | header (nav) | ✅ covered | The header shell has no independent error state of its own; the connection status indicator contained within it is the sole error surface, covered separately above |
| overflow | header (nav) | ✅ covered | Header layout targets desktop viewports (≥1280px) only in Phase 1; full tablet-width responsive behavior (UI-04) is explicit Phase 3 scope, so no overflow/wrap handling is required for the header bar this phase |
| long-text | header (nav) | ✅ covered | The header contains only the fixed wordmark "FinAlly" and the connection status label (drawn from the same fixed 3-string enum); no user-generated or variable-length text exists that requires long-text handling in Phase 1 |
