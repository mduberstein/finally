## Phase Goal

**As a** visitor watching live prices, **I want to** see at a glance whether the price feed is actually healthy, **so that** I never mistake a frozen screen for a quiet market.

<objective>
Give the header an honest three-state connection indicator that goes yellow while retrying, red when the stream is down, and recovers to green on its own — and make sure a broken stream never blanks the prices already on screen.

Purpose: MARKET-03. On a trading terminal, a stale price shown as live is worse than no price at all; this indicator is the user's only signal that what they are reading is current.
Output: a tested connection state machine, the header indicator, and staleness-aware wiring in the price stream hook.
</objective>

Write `frontend/lib/connection.test.ts` FIRST covering every case in the behavior block, and confirm it fails before the implementation exists.

Then create `frontend/lib/connection.ts` exporting `DISCONNECTED_AFTER_ERRORS` set to 3, `STALE_AFTER_MS` set to 10000, a `ConnectionState` type holding `status: ConnectionStatus`, `consecutiveErrors: number`, and `lastMessageAt: number`, plus:
- `initialConnectionState(now: number): ConnectionState` — status "reconnecting", zero errors, `lastMessageAt` set to `now`.
- `reduceConnection(state: ConnectionState, event: ConnectionEvent, now: number): ConnectionState` — a pure reducer over the event kinds "open", "message", "error", and "tick".
- `statusLabel(status: ConnectionStatus): string` — the three fixed strings.

Reducer rules: "open" and "message" both clear the error count and set status to "connected", and "message" also stamps `lastMessageAt`; "error" increments the error count and yields "disconnected" once the count reaches `DISCONNECTED_AFTER_ERRORS`, otherwise "reconnecting"; "tick" downgrades a "connected" state to "reconnecting" when `now - lastMessageAt` is at least `STALE_AFTER_MS`, and otherwise returns the state unchanged.

The staleness rule is the point of this module, not an extra. A native `EventSource` can sit in the OPEN state against a wedged connection indefinitely, so trusting the socket alone would paint the dot green over frozen prices. `STALE_AFTER_MS` of 10000 is comfortably above the 500ms stream cadence and the 15s server ping is not counted as a price event, so a genuinely idle-but-healthy stream is still reported honestly rather than being masked by keepalive traffic.

Inject `now` as a parameter and never read the clock inside this module, so the staleness and retry-threshold behavior is testable without fake timers.

## Flagged assumptions

1. **Yellow-to-red threshold.** No source artifact defines when "reconnecting" becomes "disconnected"; the ROADMAP only requires that all three states exist. Assumption: 3 consecutive EventSource error events. Chosen so a single transient blip stays yellow while a genuinely dead backend reaches red within a few seconds. Adjustable in one constant.
2. **Staleness window of 10 seconds.** Also unspecified. Assumption: 10000ms — twenty times the 500ms stream cadence, so normal jitter never trips it, and short enough that a wedged connection is caught before the user has read many stale prices.
3. **Error copy placement.** The UI-SPEC Copywriting Contract says the error sentence is "shown as the connection-dot label text when disconnected", while the UI Considerations table says the label is always one of three fixed short strings. Assumption: the visible label stays the three-string enum and the longer sentence rides as the accessible description, which honors both rows and the "no separate error banner" rule. Flag for the developer if the visible long-form label was intended.
