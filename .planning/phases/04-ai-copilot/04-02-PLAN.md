## Phase Goal

**As a** trader running a simulated portfolio, **I want to** converse with an AI assistant that analyzes my portfolio and acts on it through natural language, **so that** I can ask questions and place trades in plain English instead of reading tables and filling in forms.

<objective>
Put a real chat panel in the browser: the reserved AI Copilot slot becomes a scrolling transcript of user and assistant bubbles fed by `GET /api/chat/history` on mount and `POST /api/chat` on send, with a pinned input row, an animated typing-dots indicator while the assistant thinks, and an inline error when the request cannot be reached.

Purpose: CHAT-01's user-facing half, CHAT-06's restore-on-reload half, and all of CHAT-07. Plan 01 proved the server path; this slice is what makes it a product rather than a curl target.
Output: `ChatPanel`, `ChatMessage`, and `ChatTypingIndicator` components plus the pure `frontend/lib/chat.ts` module, replacing `ChatPlaceholder` in `page.tsx`.
</objective>

## Flagged assumptions

Recorded rather than silently decided.

1. **The panel heading moves out of the 256px box.** `04-UI-SPEC.md`'s Layout section describes the reserved shell as a section containing an `h2` ABOVE a `h-64 min-h-64` box, but `ChatPlaceholder.tsx` actually renders the "AI Copilot" title INSIDE that box. Adopting the UI-SPEC shape adds roughly 38 pixels of heading plus margin above the box, so the section grows by that much. Assumption: adopt the UI-SPEC shape anyway, because the chat panel is the last element in its column with nothing rendered below it — the reflow Phase 3 D-03 guarded against cannot occur — and because every sibling panel (Heatmap, PnlChart, PositionsTable, TradeBar) already puts its heading above its content box. The content box height itself, the section chrome, and the padding are unchanged.
2. **Optimistic user bubble with rollback.** `TradeBar` and `WatchlistAddForm` are both strictly non-optimistic, but D-03 requires the typing indicator to occupy the position of the NEXT assistant bubble, which only reads correctly if the user's bubble is already visible. Assumption: append the user bubble immediately and roll it back on failure, restoring the draft. This keeps the client transcript identical to what a reload would restore, since Plan 01 persists nothing on a failed request.
3. **No component-level tests.** `@testing-library/react` is not a dependency and every existing frontend test targets a pure `lib/` module. Assumption: keep that boundary — `lib/chat.ts` is unit-tested, the components are covered by TypeScript, ESLint, the production build, and the Task 3 browser checkpoint. Adding a component test harness is scope this phase did not ask for. `04-RESEARCH.md`'s Wave 0 list mentioned component test files; this is the deliberate deviation.
4. **The AI Copilot panel has no distinct state for a missing credential or a misconfigured mock flag** — `04-UI-SPEC.md`'s one unresolved UI consideration. Assumption: it surfaces as the ordinary send-failure error, because from the browser's side a 500 from a keyless backend is indistinguishable from any other failed send, and inventing a second error treatment would require the backend to disclose its configuration state to the client.
5. **The empty-state prompt renders with the input row still visible.** `04-UI-SPEC.md` specifies the prompt but not whether the input is present alongside it. Assumption: yes — a user must be able to start the conversation, so the prompt replaces only the transcript, not the whole box.
