## Layout — Fills the Existing Reserved Slot (unchanged chrome, per D-02/D-03)

`ChatPlaceholder.tsx`'s outer chrome is fixed by Phase 3 D-03 and must not change: `<section className="rounded-md border border-border bg-card p-6">` with an `<h2 className="text-heading mb-4 text-foreground">AI Copilot</h2>` above a `h-64 min-h-64` content box — identical shell to `Heatmap`/`PnlChart`. `ChatPanel.tsx` replaces only the *inside* of that `h-64 min-h-64` box; the section, heading, padding, and box height do not change, so no sibling panel reflows (Phase 3 D-03's whole reason for reserving the slot early).

Inside the unchanged `h-64 min-h-64` box, `ChatPanel` is a `flex flex-col` with two regions:

```
┌─────────────────────────── h-64 min-h-64 box ───────────────────────────┐
│  Transcript (flex-1, overflow-y-auto)                                    │
│    - user bubbles right-aligned                                          │
│    - assistant bubbles left-aligned, yellow left-stripe                  │
│    - executed action cards beneath their assistant bubble                │
│    - typing-dots indicator in place of the next assistant bubble (D-03)  │
│  ─────────────────────────────────────────────────────────────────────  │
│  Input row (shrink-0, pinned) — Input + Send button (D-02)               │
└────────────────────────────────────────────────────────────────────────┘
```

- Transcript region: `flex-1 overflow-y-auto flex flex-col gap-2`, auto-scrolls to the newest message on load and on every new message (D-11) via a scroll-into-view ref on the last element.
- Input row: `shrink-0 flex items-center gap-2 pt-2` — pinned below the scrolling transcript, matching `TradeBar`'s fixed-input convention (D-02).
- 256px is a small viewport for a transcript. This is an accepted tradeoff of honoring the Phase 3 D-03 constraint verbatim ("must fit into without changing") rather than resizing the slot — the transcript scrolls, it does not need to show full history at once.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from Phases 1-3, carried forward:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap inside action cards, typing-dot gaps |
| sm | 8px | Gap between transcript messages, bubble internal padding (vertical) |
| md | 16px | Panel internal padding is inherited unchanged from the section shell |
| lg | 24px | Section padding (`p-6`, unchanged from the reserved shell) |
| xl | 32px | Not used within the chat box itself (256px box has no room) |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions: bubble max-width is `80%` of the box (a proportional constraint, not a spacing token) — this is a Tailwind arbitrary utility `max-w-[80%]`, kept because a fixed-px bubble width would be wrong at the tablet-stack breakpoint where the box is full-width.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Send" — filled `bg-submit` button beside the message input (matches Buy/Sell/Add's established purple-submit convention). Disabled until the input holds non-whitespace text and while a request is in flight. |
| Message input placeholder | "Ask about your portfolio, or tell me to trade..." |
| Empty state (fresh conversation, no messages yet) | Single-line prompt (not a heading/body pair — same treatment as Phase 3's empty main-chart prompt): "Ask about your portfolio, or tell me to buy, sell, or edit your watchlist." |
| Loading indicator | No text — the typing-dots bubble (D-03) is the sole loading signal; input and Send button disable simultaneously (`submitting` state, same pattern as `TradeBar`/`WatchlistAddForm`) |
| Executed trade action card | "✓ Bought {quantity} {TICKER} @ ${price}" or "✓ Sold {quantity} {TICKER} @ ${price}" — `CheckCircle2` icon, exact fill price from the executed trade, `numeric` tabular-nums on the price |
| Executed watchlist action card | "✓ Added {TICKER} to watchlist" or "✓ Removed {TICKER} from watchlist" |
| Failed trade / watchlist action | **No action card** (see Claude's Discretion resolution below) — the explanation lives entirely in the assistant's own prose message bubble, in the exact-numbers style D-06 specifies, e.g. "Can't buy 50 TSLA — that's $12,450 but you have $8,200 cash." The backend constructs this text; the frontend renders it as an ordinary assistant bubble, no special-casing. |
| Error state — send request failed (network/5xx) | "Couldn't reach the assistant — try again." (inline, `role="alert"`, `text-down`, beneath the input row; clears on the next input change — same convention as `TradeBar`/`WatchlistAddForm`) |
| Error state — malformed LLM response (backend-side parse failure) | Not a distinct frontend state — the backend's fallback `ChatResponse.message` ("Something went wrong processing that — try rephrasing.") renders as a normal assistant bubble; the frontend does not need to detect or special-case this condition |
| Error state — history fetch failed on page load | Transcript keeps whatever it has (empty, if nothing loaded yet) and shows the same empty-state prompt above; no dedicated banner — matches Phase 3's resilience precedent of never clearing to a hard error screen |
| Destructive confirmation | Not applicable — chat-initiated trades and watchlist changes are instant with no confirmation dialog, consistent with PLAN.md's no-confirmation-dialog philosophy (same resolution as Phase 2 trades and Phase 3 watchlist removal) |

### Claude's Discretion — Resolved

1. **Exact action-card styling:** `rounded-md border border-border bg-card px-3 py-2 text-body`, plus a 2px `border-l-2 border-l-up` left stripe and a `CheckCircle2` icon (14px, `text-up`) inline before the copy. Stacked with `mt-2` beneath the assistant bubble that produced it; multiple action cards in one turn stack with `mt-1` between them.
2. **Typing-dots implementation:** CSS-only, no library. Three `size-1.5 rounded-full bg-muted-foreground` dots inside the same bubble shell as an assistant message (`bg-muted`, `border-l-2 border-l-[#ecad0a]`, left-aligned), each dot pulsing via a shared `@keyframes typing-dot` (opacity 0.3 → 1 → 0.3) with staggered `animation-delay` (0ms / 150ms / 300ms), `1.2s` loop, `infinite`. Respects `prefers-reduced-motion: reduce` — falls back to three static dots at fixed 0.6 opacity, no animation (same pattern already used for the price-flash animations in `globals.css`).
3. **History cap:** 100 messages. `GET /api/chat/history` returns the newest 100 in chronological order (mirrors `get_portfolio_history()`'s DESC-then-reverse pattern per 04-RESEARCH.md Pitfall 5).
4. **Failed-trade action card treatment:** No card at all for failures — only successful, executed actions get a card. A failure is nothing but prose (the assistant's own explanation), because rendering any card-like UI for something that did *not* happen risks implying it did. This keeps the visual rule simple and unambiguous: **if you see a card, it happened.**
