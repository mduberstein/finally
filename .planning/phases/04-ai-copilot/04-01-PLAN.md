## Phase Goal

**As a** trader running a simulated portfolio, **I want to** converse with an AI assistant that analyzes my portfolio and acts on it through natural language, **so that** I can ask questions and place trades in plain English instead of reading tables and filling in forms.

<objective>
Prove the whole chat path end to end on the server: a message posted to `POST /api/chat` reaches OpenRouter/Cerebras through LiteLLM with structured outputs, comes back parsed into a `ChatResponse`, gets persisted to `chat_messages`, and returns as one complete JSON body — with `LLM_MOCK=true` short-circuiting the external call entirely. This is the phase's tracer. Plans 02-04 expand out from it: the browser transcript, the portfolio-aware prompt with auto-executed actions, and the action cards.

Purpose: this is the only slice that crosses every new layer the phase introduces (a new backend package, a new external provider, a new dependency, a new secret, and a table that has existed unused since Phase 1). Proving it first costs one commit if the LiteLLM/Cerebras structured-output contract does not behave as researched, instead of four.
Output: the `backend/app/chat/` package owning the whole `/api/chat` surface, plus the `load_dotenv()` call that makes the OpenRouter credential visible to a bare `uv run uvicorn`.
</objective>

**Schema — `backend/app/chat/models.py`.**
Plain `pydantic.BaseModel` subclasses with NO field-level constraints on the model handed to `response_format`: Cerebras strict mode rejects regex `pattern`, string `format`, and array `minItems`/`maxItems`, and LiteLLM already emits `additionalProperties: false` plus `strict: true` from a bare `BaseModel` (04-RESEARCH.md Pattern 4). Define:
- `TradeAction` — `ticker: str`, `side: Literal["buy", "sell"]`, `quantity: int`. `int` and enums are both supported strict-mode constructs; `int` is D-09's whole-share constraint expressed in the schema itself.
- `WatchlistAction` — `ticker: str`, `action: Literal["add", "remove"]`.
- `ChatResponse` — `message: str`, `trades: list[TradeAction] = []`, `watchlist_changes: list[WatchlistAction] = []`. Field names come straight from `planning/PLAN.md` section 9 and are not open to renaming.
- `MAX_MESSAGE_LENGTH = 4000` — the inbound user-message cap, counted in Python string code points (`len()` on a `str`), which is the only length definition this codebase needs; no byte or grapheme-cluster measurement is involved anywhere.
- `PARSE_FALLBACK_MESSAGE` — exactly `Something went wrong processing that — try rephrasing.` (em dash), the string `04-UI-SPEC.md`'s Copywriting Contract commits the backend to.

Also document the persisted `actions` payload contract here as a module docstring section, because Plans 03 and 04 both build against it. One JSON array whose elements are objects with a `type` key of either `trade` or `watchlist`, a `status` key of either `executed` or `failed`, and a `ticker` key; a `trade` element additionally carries `side` and `quantity`, plus `price` when executed or `code` when failed; a `watchlist` element additionally carries `action`, plus `code` when failed. Plan 01 always persists an empty array — the executing loop is Plan 03 — but the contract is fixed now so both later plans agree.

**LLM boundary — `backend/app/chat/llm.py`.**
Module-level `from litellm import completion`, `MODEL = "openrouter/openai/gpt-oss-120b"`, `EXTRA_BODY = {"provider": {"order": ["cerebras"]}}` — copied from the skill, not paraphrased.
- `call_llm(messages: list[dict]) -> str` — first read `LLM_MOCK` from the environment; when it is the string `true` (case-insensitively, after stripping) return `mock_response(messages).model_dump_json()` and return before touching `completion`, so a mock run issues zero outbound requests (CHAT-09). Otherwise call `completion(model=MODEL, messages=messages, response_format=ChatResponse, reasoning_effort="low", extra_body=EXTRA_BODY)` and return `response.choices[0].message.content`.
- `mock_response(messages: list[dict]) -> ChatResponse` — deterministic: the same input yields a byte-identical `ChatResponse` on every call, with no clock, no randomness, and no counter. Return a fixed terse acknowledgement with both action lists empty. Determinism and the absence of a network call are the only properties CHAT-09 requires; the canned wording is yours. Plan 03 extends this to react to trade-shaped phrasing for Phase 5's E2E suite — leave the signature able to inspect `messages` so that extension needs no rewrite.
- `parse_response(raw: str) -> ChatResponse` — a pure function taking a string and returning a model, deliberately separated from `call_llm` so TEST-02 can exercise it with fixtures and no LiteLLM involvement at all. Wrap `ChatResponse.model_validate_json(raw)` in `try` / `except (ValidationError, ValueError)`; on failure log at warning level with a truncated excerpt of `raw` (a few hundred characters at most) and return `ChatResponse(message=PARSE_FALLBACK_MESSAGE)`. Log the excerpt only — no request object, no headers, no environment. This is `04-RESEARCH.md` Pitfall 2's mitigation: `gpt-oss-120b` has documented cases on other inference backends of leaking reasoning text alongside or instead of the structured payload, and a leaked-reasoning response must degrade to a readable reply rather than a 500.
- This module never reads, stores, logs, or returns the OpenRouter credential; LiteLLM resolves it from the process environment on its own.

**Service — `backend/app/chat/service.py`.**

Use `uuid.uuid4().hex` ids and `datetime.now(UTC).isoformat()` timestamps. Insert the user row first so `ORDER BY created_at, rowid` restores the turn in the order it happened.

**Router — `backend/app/chat/routes.py`.**
`create_chat_router(cache: PriceCache) -> APIRouter`, the same factory shape as `create_portfolio_router` and `create_watchlist_router`.
- `ChatRequest(BaseModel)` with one field: `message`, typed with a `pydantic.StringConstraints` annotation that strips surrounding whitespace, requires `min_length=1`, and caps at `MAX_MESSAGE_LENGTH`. Stripping before the minimum-length check is what makes a whitespace-only body a 422 rather than an empty prompt sent to the model, and the maximum is the light denial-of-service mitigation `04-RESEARCH.md`'s Security Domain recommends. FastAPI returns 422 for both automatically — no handler code needed.
- `POST /api/chat` — `await run_in_threadpool(handle_chat_message, request.message, cache)` and return the dict. `completion` is synchronous; calling it on the event loop would stall every other request including the SSE price stream for the whole round-trip, which this project's own CLAUDE.md lists as an anti-pattern.
- `GET /api/chat/history` — `await run_in_threadpool(get_recent_messages)` returning `list[dict]`. This endpoint is NOT in `planning/PLAN.md` section 8, which lists only `POST /api/chat`; `04-RESEARCH.md` Open Question 1 identified the gap and CHAT-06/D-10 require it. The path mirrors `GET /api/portfolio/history`'s existing naming.
- No `EventSourceResponse`, no `sse_starlette` import, no chunked response anywhere in this package. `planning/PLAN.md` section 9 is explicit that Cerebras is fast enough that a loading indicator suffices, and CHAT-01 asks for one complete JSON body.
