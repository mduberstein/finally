**Environment seams that already exist (do not create new env vars):**

`backend/app/db/database.py` `db_path()` reads `FINALLY_DB_PATH`; when unset it falls back to `Path(__file__).resolve().parents[3] / "db" / "finally.db"`. Inside the image, `database.py` sits at `/app/app/db/database.py`, so `parents[3]` is `/` and the fallback would resolve to `/db/finally.db`. The env var must be set explicitly.

`backend/app/main.py` resolves the static directory as `Path(os.getenv("FINALLY_STATIC_DIR", str(Path(__file__).resolve().parents[2] / "backend" / "static")))` and mounts it only `if _static_dir.is_dir()`. A wrong path does not raise — it silently serves only `/api/*` and 404s on `/`. The env var must be set explicitly.

`backend/app/main.py` calls `load_dotenv(Path(__file__).resolve().parents[2] / ".env")` at import. Inside the image that resolves to `/.env`, which will not exist; `load_dotenv` no-ops silently. This is correct and intentional — configuration reaches the container through `docker run --env-file`, and `load_dotenv` never overrides values already in the process environment.

`backend/app/main.py` exposes `GET /api/health` returning `{"status": "ok"}` — the readiness poll target for every script and healthcheck in this phase.

`backend/app/db/database.py` `initialize()` calls `path.parent.mkdir(parents=True, exist_ok=True)` then runs `schema.sql` with `CREATE TABLE IF NOT EXISTS` and seeds with `INSERT OR IGNORE`. It is purely additive and never destructive, so pointing it at an existing `db/finally.db` is safe. The `mkdir` is exactly why a missing bind mount degrades silently — it happily creates an ephemeral `/app/db` inside the container's writable layer.

| Boundary | Description |
