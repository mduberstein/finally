## Phase Goal

**As a** trader with $10,000 of simulated cash, **I want to** buy and sell shares at the live market price and watch my cash, positions, and total value respond immediately, **so that** the terminal becomes a place I can actually trade rather than only watch.

<objective>
Prove the whole trading path end to end on one slice: a Buy typed into the trade bar reaches a server-authoritative fill price, commits atomically to SQLite, appends a trade-history row, and comes back as a changed cash balance and a live-moving total value in the header.

Purpose: PORT-01, PORT-02, PORT-07, PORT-10, UI-03, and D-01/D-02/D-03. Everything Phase 2 and Phase 4 add hangs off this write path — proving it now costs one commit if the transaction shape is wrong instead of ten.
Output: the `backend/app/portfolio/` package, both portfolio endpoints registered in `main.py`, a `TradeBar` component, the pure `derivePortfolioValue` overlay, and a header that shows live cash and total value.
</objective>

Locked decisions this task implements:

**Domain models — `backend/app/portfolio/models.py`.**
Follow `app/market/models.py` style: `@dataclass(frozen=True, slots=True)` with full type hints.
- `Position` with `ticker: str`, `quantity: float`, `avg_cost: float`.
- `TradeResult` with `ticker: str`, `side: str`, `quantity: float`, `price: float`, `executed_at: str`, `cash_balance: float` — the post-trade cash, so a caller never has to guess.
- An exception family rooted at `TradeRejected(Exception)`, each subclass carrying the data the UI copy needs: `UntradableTickerError(ticker)`, `InsufficientCashError(ticker, cost, cash_balance)`, `InsufficientSharesError(ticker, owned)`. Give each a `code` class attribute holding the strings `untradable_ticker`, `insufficient_cash`, and `insufficient_shares`, and a `detail() -> dict` returning that code plus its data fields. The frontend renders the exact copy; the backend only supplies a machine-checkable payload. `InsufficientSharesError` is defined here even though only Plan 02 raises it, so the exception family is one artifact rather than two.

**Trade execution and snapshot — `backend/app/portfolio/service.py`.**
Two public functions, both plain and HTTP-agnostic so Phase 4's chat flow can import and call them directly rather than re-implementing validation.

`execute_trade(ticker: str, side: str, quantity: float, cache: PriceCache) -> TradeResult`
Type `quantity` as `float` at this layer even though this phase's endpoint constrains it to `int` — Phase 4 adds fractional LLM-initiated trades and should not need a signature change (D-03 keeps the whole-share rule at the request model, and the schema's REAL columns already accommodate fractions).
1. Uppercase the incoming ticker before anything else. `PriceCache` keys are always uppercase because `DEFAULT_TICKERS` is; a lowercase symbol would otherwise be wrongly refused as untradable.
2. Read the fill price with `cache.get(ticker)`. Raise `UntradableTickerError` when it returns `None` — that is D-02's tradability rule and it needs no watchlist query, because a ticker only reaches the cache by being on the watchlist. Never call a market source's `fetch()`; `PriceCache` is the single sanctioned price reader.
3. Open a connection with `sqlite3.connect(db_path(), isolation_level=None)`, set `row_factory = sqlite3.Row`, and wrap it in `contextlib.closing`. Issue `BEGIN IMMEDIATE` as the first statement, before any read. Autocommit plus an explicit immediate begin takes the write lock up front, so a second concurrent trade blocks until this one commits instead of both validating against the same stale cash balance and the later commit clobbering the earlier. The legacy default only begins a transaction on the first write statement, which is exactly the gap.
4. Inside the transaction: read `cash_balance` from `users_profile` and the existing `positions` row for this user and ticker. Compute `cost = quantity * price` in plain float — the columns are REAL, and rounding at intermediate steps is the mistake this codebase already avoids (`round` is applied once, at the response boundary).
5. Buy validation: raise `InsufficientCashError` when `cost > cash_balance`. Use a strict greater-than so a buy costing exactly the available cash succeeds and leaves the balance at zero.
6. Buy write: subtract `cost` from `cash_balance`, upsert the `positions` row with the new quantity and a weighted average cost `((old_qty * old_avg) + cost) / new_qty`, and insert one `trades` row. Give new rows a `uuid.uuid4().hex` id and an ISO-8601 UTC timestamp from `datetime.now(UTC).isoformat()`, matching `database.py`.
7. Rows in the trade-history table are only ever inserted. This module must contain no statement that modifies or removes a trade-history row (PORT-10).
8. `COMMIT` on success; `ROLLBACK` and re-raise on any exception, so a refused trade leaves cash and positions byte-identical.
9. Every statement uses `?` placeholders. No SQL is ever built by string formatting or f-string interpolation — the same rule `01-SECURITY.md` locked in for Phase 1 (T-02-01).

`get_portfolio(cache: PriceCache) -> dict`
Read-only, so it uses the existing `db.connect()` + `closing()` shape rather than the immediate-transaction variant. Return `{"cash_balance": float, "positions_value": float, "total_value": float, "positions": [...]}`. Each position entry mirrors the `_watchlist_entry` shape: `ticker`, `quantity`, `avg_cost`, `price` (from `cache.get`, `None` when unknown), `unrealized_pnl` (`quantity * (price - avg_cost)`, `None` when the price is unknown), and `change_percent` (`(price - avg_cost) / avg_cost * 100`, rounded to 4 places, `None` when the price is unknown). `positions_value` sums `quantity * price` across positions with a known price; `total_value` is `cash_balance + positions_value`.

**Router — `backend/app/portfolio/routes.py`.**
`create_portfolio_router(cache: PriceCache) -> APIRouter`, the exact shape of `create_stream_router`, so the endpoints stay testable without a full app lifespan.
- `TradeRequest(BaseModel)` with `ticker: str`, `side: Literal["buy", "sell"]`, and `quantity: int = Field(gt=0)`. The integer type plus the positive constraint is D-03's whole-share rule and rejects zero, negative, and fractional quantities before any database access. The model declares no field for the fill price at all — D-01 forbids trusting a client-supplied one, and the surest way to honor that is for the field not to exist.
- `GET /api/portfolio` returns `await run_in_threadpool(get_portfolio, cache)`.
- `POST /api/portfolio/trade` calls `execute_trade` through `run_in_threadpool` and returns the `TradeResult` as a dict. Catch `TradeRejected` and re-raise as `HTTPException(status_code=400, detail=error.detail())`. Use 400, not 422: FastAPI generates 422 itself for request-shape failures, and a frontend that cannot tell "you mistyped the request" from "you cannot afford this" has no way to choose the right message.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `POST /api/portfolio/trade` | Untrusted ticker, side, and quantity cross into the trade write path |
