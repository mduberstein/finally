## Phase Goal

**As a** trader with $10,000 of simulated cash, **I want to** buy and sell shares at the live market price and watch my cash, positions, and total value respond immediately, **so that** the terminal becomes a place I can actually trade rather than only watch.

<objective>
Give the trader the readout that makes the portfolio legible: one row per open position showing ticker, quantity, average cost, current price, unrealized P&L, and percent change, all moving with the same live price stream that already drives the header.

Purpose: PORT-06 and the position half of PORT-07. Cash and a total value alone do not tell a trader which holding is working; the positions table is where that answer lives.
Output: `derivePositionRows` in the tested `frontend/lib/portfolio.ts` module, a `PositionsTable`/`PositionRow` pair mirroring `Watchlist`/`WatchlistRow`, and both wired into the page.
</objective>

Return the top-level null for a null snapshot so the table can distinguish the pre-fetch state from a genuinely empty portfolio — that distinction is what selects skeleton rows over the empty state. Keep the module pure: no fetch, no polling timer, no React import.

Do not round inside this function. The stored and computed values stay at full double precision and `formatPrice` truncates to two decimals at the render boundary only, which is the same split the codebase already uses for prices.
